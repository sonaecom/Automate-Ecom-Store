# Account security check

Dry run follows `{baseDir}/modules/ops/dry-run.md`: walk the steps, take the screenshots, write the report, and do not click Save, Submit, or Send.

Alert only. Do not change a password, a bank account, a phone number, or a sub-account. Do not approve a new device. The owner does those clicks.

Policy gate action is `read`.

## When to use

A scheduled look, or the owner asks whether the seller login looks normal.

## Steps

1. Open the security or login-history page once. Read unusual logins and new devices. Copy the time and the label the page shows. Do not copy a session token.
2. Open the bank-account page only if it is a view. Record the last 4 digits and whether the page says the account changed recently. Cover a full account number in any screenshot. Never press edit.
3. Open sub-account or staff permissions. List roles as shown. If a role can pay or withdraw and the owner did not name that person, alert. Do not remove the person yourself.
4. Alert in chat. One message. No customer email.

No dashboard tab. The alert is the output.

## Platform notes

Shopee: Account or Security settings. TikTok Shop: Account security or login activity. Lazada: Account settings. Use the menu you see. If a page offers to "verify" by changing the password, leave it.

## QC

The alert matches the page. The screenshot hides full bank numbers. Nothing was clicked except open and back.

## Stop

Any button would change the login, the bank, or a permission. You would need a one-time code and the owner is not watching.

## Report

What looked new, last 4 digits only if a bank row was on screen, read time. No passwords and no tokens.
